# 環境構築の極意 (Docker / WSL2 / Ubuntu / Proxmox)

いやー、環境構築って本当に沼ですよね笑。
でも安心してください！ここで紹介するポイントを押さえておけば、後から「あれ？動かないぞ…」ってなるのをガッツリ防げると思っています！

## 1. Docker / Docker Compose / DevContainer の話

### MacやWindowsでDockerを使う時の落とし穴
まず知っておいてほしいのが、**Dockerって元々Linuxのカーネル機能（CgroupsやNamespaces）に依存している**というわけです。
つまり、macOSやWindowsでDockerを動かす時って、実は裏で「ハイパーバイザ上のLinux VM」が動いてるんですよ。これ、ネイティブのLinux環境と比べると、I/Oやコンテナの起動にどうしてもオーバーヘッドがかかっちゃうんですよね。なので「なんかMacだとDocker遅いな〜」って感じるのは、仕様だから仕方ないんです笑。

### マルチステージビルドでスリム化！
C++とかRustみたいなコンパイル言語を使ってるなら、**マルチステージビルド**は絶対やってほしいテクニックです！
ビルド用と実行用のコンテナをパキッと分けることで、デプロイ用のイメージから重たいコンパイラとかビルド依存を全部削ぎ落とせるんですよね。これだけでイメージサイズが劇的に軽くなるので、超おすすめです。

### チーム開発なら「DevContainer」一択！
「俺のPC環境だと動くんだけどなぁ…」って言っちゃうこと、ありますよね笑。
あれを撲滅するためにも、VS Codeの**DevContainer (`.devcontainer`)** を導入しちゃいましょう！これを設定しておけば、チーム全員で開発環境からツールチェーン、コンテナの設定まで完全に統一できるというわけです。もう環境構築で消耗するのはやめにしましょう！

## 2. WSL2 (Windows Subsystem for Linux 2) を使い倒す

### USBデバイスのパススルー (`usbipd-win`)
WSL2を使っていると、「ST-LinkとかCANアナライザ、LiDARなんかのUSBデバイスが認識しない！」って壁に必ずぶち当たりますよね。
そんな時は迷わず **`usbipd-win`** を使ってください！
PowerShell側で `usbipd bind` しておいて、WSL2起動時にサクッと自動アタッチされるようなスクリプトを組んでおくと、毎回の開発効率が爆上がりしますよ。

### WSL2カスタムカーネルビルドのすゝめ
実はWSL2の標準カーネルって、`joydev`（ジョイスティック `/dev/input/js*`）とか仮想CANが無効化されてたりするんですよね。ロボティクスやってるとこれが結構痛いんです。
「じゃあどうするの？」って話ですが、Microsoftが公開しているWSL2用のLinuxカーネルソースを持ってきて、自分でカスタムビルドしちゃうのが手っ取り早いです！
`make menuconfig` で `CONFIG_INPUT_JOYDEV=y` とかをオンにしてビルドして、それを `.wslconfig` に指定して起動するだけ。ちょっとハードル高く感じるかもしれないですが、やってみると意外とすんなりいけるのでぜひ挑戦してみてくださいね！
