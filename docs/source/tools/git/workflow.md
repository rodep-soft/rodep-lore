# チームで戦うためのGit・GitHub運用術 🚀

お疲れ様です！今回は、私たちのチームにおける「Gitの高度な使い方・運用フロー・開発プラクティス」について、ガッツリ語っていこうと思います🔥

「Gitってとりあえずcommitしてpushすればいいんでしょ？」って思ってるそこのあなた！
チーム開発でのGitは、単なるバージョン管理ツールじゃなくて**「コミュニケーションツール」**なんですよね笑。
というわけで、僕らが普段どんな思想でGitを回しているのか、ハマりどころも含めて全部教えちゃいます！

## 1. コミットとブランチの運用思想 〜完璧主義は捨てろ！〜

### 「実機で動くまでコミットしません！」はマジでNG 🙅‍♂️
よくあるアンチパターンとして、「完璧に動く状態になるまでコミットしない」っていうのがあるんですけど、これ**絶対やめてください**笑。
コードが途中でも、トピックブランチを切って細かくコミット＆プッシュしていくのが正解です。
「でもビルド通らないし…」って時は、`colconignore`を置いてビルド対象から外しちゃえばOK！
とにかくGitHubに上げて、チームのみんなから早めにレビューをもらえる状態にすることが大事なんですよね。

### PRは生鮮食品！放置すると腐ります 🐟
PR（プルリク）を長期間放置するとどうなるか…そう、**地獄のコンフリクト**が待っています笑。
メインブランチとの差分が広がりすぎるとマジで解決が困難になるので、Draft PRやIssue、Discussionsを使って、「今こんなことやってます〜」って透明性高く進捗を共有していきましょう！

### Discordの雑談で終わらせないで！ 📝
バグ報告とか、WSL2/Dockerの環境構築でハマったこと、新しいタスクなんかをDiscordでサラッと流してませんか？
それ、絶対リポジトリのIssueかDiscussionsに残してください！
あとから「あれどうやって解決したっけ…」ってなった時に検索できなくて詰むというわけです。知見は資産ですよ！

## 2. 安全な履歴操作 〜`git reset --hard`は諸刃の剣〜

### 共有リポジトリでの `--hard` はマジで怖い 😱
チーム開発中に不用意に `git reset --hard` を叩くのは、作業データが消し飛ぶリスクが高いのでマジで気をつけてください。
「ちょっと作業退避させたいな〜」って時は、おとなしく `git stash push` を使うか、ちゃんと履歴を残す `git reset --soft` を検討しましょう。後輩が `--hard` で泣いてる姿、何度も見てきましたからね…笑。

## 3. サブモジュール（Git Submodule）とリポジトリ分離 〜巨大化を防げ！〜

### 巨大なコードは `git submodule` で管理する 📦
micro-ROSとかモータードライバみたいな、他所が作ってる巨大なコードを直接プロジェクトに突っ込むのはNGです。
リポジトリが爆発的に肥大化しちゃうんですよね。
そういう時は、独立したリポジトリとしてForkして、`git submodule` で管理するのがスマートというわけです。これで `git clone` も爆速になります！

### 個人の趣味（ドットファイル）は持ち込まないで！ 🛑
nvimとかVS Codeの俺得設定（ドットファイル）を、チームの共通リポジトリにコミットしたりSubmodule化するのはやめましょう笑。
プロジェクトのリポジトリには、あくまで**チーム共通の開発設定だけ**を入れるのがマナーです。

## 4. Git 事故とトラブルシューティング 〜よくある罠と回避策〜

### `.gitignore` 忘れはブラウザクラッシュの元 💥
`a.out` とか `main.exe`、`build/` フォルダみたいなバイナリをうっかりコミットしちゃうと、GitHub上で差分を見ようとした時にブラウザがフリーズします（実話）。
もし間違えてpushしちゃったら、慌てずに `git rm --cached` で追跡を解除して、`.gitignore` にサクッと追記しておきましょう！

### 「空ディレクトリの罠」に気をつけろ 🕳️
これめっちゃハマる人が多いんですけど、Gitって**空のディレクトリを追跡してくれない**んですよ。
ローカルで手動で作った空フォルダのおかげでビルドが通ってても、CI（GitHub Actionsとか）で回した時に「ディレクトリが存在しません！」って怒られるというわけです。`.gitkeep` 置くか、生成処理をスクリプトに入れましょうね！

### 1号機・2号機のコード、どう管理する？ 🤖🤖
機体ごとのパラメータ調整とかを直接メインブランチにマージしたら、一瞬でコードが崩壊します笑。
