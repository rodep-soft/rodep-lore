# WSL2の高度な活用とハードウェア連携

Windows Subsystem for Linux 2 (WSL2) は、Windows環境における開発体験を劇的に変革しました。完全なLinuxカーネルの搭載により、高い互換性とパフォーマンスを実現していますが、組み込み開発や特殊なネットワーク要件においては、デフォルトの構成から一歩踏み込んだチューニングが求められます。

## デバイスパススルーとudevによる自動化

ロボティクスやIoT機器の開発において、ST-Link、CANアナライザ、LiDARなどの専用USBデバイスを扱う場面があります。WSL2単体ではこれらのデバイスを直接認識できませんが、オープンソースツールである`usbipd-win`を導入することで、Windows側のUSBデバイスをWSL2へパススルーすることが可能となります。

運用をさらに洗練させるためには、Linux側でudevルールを記述し、デバイス接続時に固定のシンボリックリンクや適切なパーミッション（例: `MODE="0666"`）を自動付与する仕組みを構築します。これをWindows側のバッチ処理やPowerShellスクリプトと連携させることで、デバイスを接続するだけでシームレスに開発環境からアクセスできる状態を作り出すことができます。

## カスタムカーネルのビルドとsystemdの統合

WSL2が提供する標準のカーネルは、軽量化と汎用性を重視してコンパイルされているため、ジョイスティックデバイス（`joydev`）や仮想CAN（`vcan`）、特定のシリアル通信ドライバなどが無効化されています。これらの機能が必要な場合、Microsoftが公開しているWSL2用のLinuxカーネルソースを取得し、カスタムカーネルをビルドする必要があります。

`make menuconfig`を通じて必要なカーネルモジュールを有効化し、ビルドしたカーネルイメージを`.wslconfig`ファイルで指定することで、独自の要件を満たす環境を構築できます。また、最近のWSL2アップデートにより公式にサポートされたsystemdを有効化することで、ネイティブなLinux環境と遜色のないデーモン管理が可能となり、Dockerデーモンや各種ネットワークサービスの起動がより自然な形で行えるようになります。

## ネットワークの透過性とパフォーマンス最適化

WSL2のデフォルトネットワークはNATモードで動作するため、ホスト外からのアクセスや、マルチキャストを利用するフレームワーク（ROS 2など）の通信において制約が生じます。Windows 11環境であれば、`.wslconfig`にて「Mirroredモード」を有効化することで、WSL2がWindowsホストのネットワークインターフェースを共有し、IPv6のネイティブサポートや透過的なローカルネットワーク通信が実現します。

リソース管理の面では、WSL2がホストのメモリを過剰に消費する現象を防ぐため、同じく`.wslconfig`内で`memory`や`processors`の制限を明示的に設定することが推奨されます。また、仮想ハードディスク（VHDX）のファイルサイズは自動では縮小されないため、定期的に`diskpart`コマンドを用いてコンパクション（最適化）を行う運用を取り入れることで、健全なストレージ環境を維持できます。
