# DockerとWSL2アーキテクチャにおける内部挙動

Dockerの実行環境に関する深い知見について整理します。

## Linuxネイティブ環境とWSL2の差異

DockerはmacOSやWindows上でネイティブに動作していると誤解されることがありますが、基本的にはLinuxカーネルの機能を必要とします。Windows環境においてWSL2（Windows Subsystem for Linux 2）を使用する場合、ハイパーバイザの上にWSLとWindowsカーネルが乗る構造となります。WSL2はXwaylandラッパーなどを経由して動いている構成要素もあり、コンテナの再作成（recreate）などにおいては、ネイティブLinux環境（通常10秒程度）と比較して、WSL2経由ではオーバーヘッドが生じ（13〜14秒程度）、パフォーマンスに差異が生じます。

## 依存関係解決とパッケージ管理

コンテナ内部の構築において、`dpkg -i`と`apt install`の挙動の違いを理解することは重要です。`dpkg`は対象のパッケージを展開しますが、依存関係の自動解決を行いません（これは`insmod`と`modprobe`の関係に似ています）。依存関係の不整合が生じた場合は、`apt install -f`を用いて修復する必要があります。現代のDebianベースの環境では、依存関係を透過的に解決する`apt`の利用が推奨されます。

## ビルド最適化

Dockerのビルド時間が長期化する要因の一つとして、`COPY`命令の不適切な使用や、不要なリソースのコンテキスト巻き込みが挙げられます。マルチステージビルドを活用し、中間イメージの肥大化を防ぐ設計が求められます。また、systemdを利用できない環境下では、デバイス（例えばジョイスティックなどの入力機器）を認識させるために独自のコードで対応するか、udevルールを活用したバインド等の工夫が必要です。
