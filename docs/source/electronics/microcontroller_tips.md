# 6. 電子工作・マイコン制御・通信プロトコル (STM32 / CAN / IMU)

本稿では、電子工作やマイコン制御、および通信プロトコルに関する知見を整理します。STM32やCAN通信、IMUの制御は、特有の課題に直面しやすいため、ここで要点を押さえておくことが重要です。

## (1) STM32 開発とビルド・書き込み環境

### STM32CubeMX + VS Code / Makefile 運用
STM32CubeIDEを単体で利用する構成もありますが、STM32CubeMXでペリフェラルやクロックの設定のみを行い、MakefileやCMakeとしてプロジェクトを出力する手法を推奨します。その上で、VS CodeやPlatformIOを用いて開発を行うことで、将来的な拡張性を確保しやすくなります。IDEの独自仕様に依存しないことは、開発において大きな利点となります。

### Linux 用 udev ルール設定 (`ST-Link`)
Linux環境において、ST-Link（Nucleoボード等）を接続した際、毎回 `sudo` を付与しなければ書き込みが行えない場合があります。これは、`/etc/udev/rules.d/` にパーミッション設定のルールを追加することで解決可能です。目立たない設定ではありますが、開発における無用な負担を軽減するために実施しておくべき事項と言えるでしょう。

### 非ブロッキングタイマー処理
マイコン制御の初期段階では、`delay()` 関数を使用しがちです。しかし、これを使用すると割り込みやその他の処理がすべて停止（ブロッキング）してしまうため注意が必要です。代わりに `HAL_GetTick()` を用いて、
`if (HAL_GetTick() - prev_tick >= 1000)`
のように記述し、非ブロッキングな周期処理を実装するのが定石であると考えます。

## (2) CAN 通信 (Controller Area Network) & SocketCAN

### Physical / Protocol 特性
CAN通信の論理駆動は、Recessive（1）とDominant（0）という状態によって表されますが、これはI2Cのオープンドレイン回路と概念的に類似しています。このような物理的なイメージを持っておくことは、トラブルシューティングの際に非常に有用です。

### SPI to CAN (MCP2515) と内蔵 CAN コントローラ
マイコンに内蔵されているCANコントローラを使用することが、最も低レイテンシで確実な手段です。しかし、SPI接続のCANコントローラ（MCP2515等）が使用されるケースも少なくありません。MCP2515を使用する際、クリスタル発振周波数（8MHzか16MHzか）の設定を誤り、初期化エラーに陥る事例が散見されます。予期せぬ動作不良が生じた場合は、まずこの設定を確認することをおすすめします。

### Linux SocketCAN とブリッジ
USB-CANアナライザ等をLinux上で扱う場合、`ros2socketcan` などを経由してLinuxの `can0` インターフェースと連携させるのが一般的です。これにより、Linux標準のツール（`candump` 等）を利用して直接パケット解析が可能となり、デバッグの効率が大幅に向上します。

## (3) センサー制御・信号処理 (IMU / フィルタリング)

### I2C クロックストレッチと応答確認
IMUセンサ等において、I2C通信が不安定になることがあります。そのような場合、直ちにレジスタへアクセスするのではなく、まず `HAL_I2C_IsDeviceReady()` を使用してデバイスの準備が完了しているかを確認する手順を踏むことが重要です。この確認を行うだけで、原因不明のエラーを大きく削減できるでしょう。

### IMU ドリフトと 1次ローパスフィルタ (IIR)
最後に、IMUのドリフト対策について触れておきます。角速度を単純に積分するだけではバイアス誤差が蓄積していくため、静的なキャリブレーションのみでは対処しきれません。
標準的な手法としては、まずFFTを用いてノイズの周波数帯を特定し、時定数を算出します。その上で、マイコン上に離散化された一次IIRフィルタを実装します。
式としては `val = alpha * new_val + (1 - alpha) * old_val` のようになります。このフィルタを導入することで値の安定性が飛躍的に向上するため、ぜひ検討してみてください。
