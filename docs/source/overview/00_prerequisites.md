# 開発者としての基本スキル

ロボット制御やプログラミングを学ぶ前に、まず習得しておくべき重要な基本スキルがあります。
ここでは、「情報収集」と「タイピング」についてまとめます。

## 1. 情報収集するということ

素のプログラミング能力や小手先のコマンド芸よりも、**情報収集能力**の方がはるかに大切なのではないかと思っています。
有名どころのサイトやリソース元を知っておくことは、開発において非常に役立ちます。

### Links (汎用)

1. [StackOverflow](https://stackoverflow.com/questions)
世界中であまりにも有名すぎるエンジニア向け質問サイトです。

2. [GitHub](https://github.com/)
自分でコードを上げる以外にも、他人のIssueを参考にしたり、リポジトリを覗いたりと付き合いは多いです。

3. [Qiita](https://qiita.com/)
日本語圏で一番有名なエンジニアブログサイトです。みんな使っています。

4. [Zenn](https://zenn.dev/)
こちらも日本語。Qiitaの次に有名なくらいです。

5. [Reddit](https://www.reddit.com/)
アメリカで有名なSNS。サイト内検索は微妙なので検索エンジンから情報を探すべきです。
エンジニア特化でもなければ情報の信頼性も微妙だったりするので注意が必要です。

6. [X/Twitter](https://x.com/home)
情報を探すのにはおすすめしませんが、トレンドを掴むにはおすすめです。

7. [dev.to](https://dev.to/)
英語サイト。微妙な記事も多いですが個人的によく見ます。Qiitaっぽい雰囲気です。

### AIを使うことについて

勿論、最近のAIは情報を勝手にSearchしてくれますし、精度も高いため積極的に頼って良いとは思いますが、自分で検索して解決しなければならないことも多々あるため、**自分で情報を集めることに慣れる**ことは大切だと考えています。

### 実際のところコード書くときによく見るリソース

有名どころのサイトは挙げましたが、実際コーディング中に見るのは、**専らライブラリやフレームワークのドキュメントやセンサーのデータシートなど**です。

また、Linksに載っているのはあくまで汎用サイトであり、それぞれの言語やフレームワークのフォーラムを見にいくことも多いです。
例えばROSだったら ROS Discourse などですね。

所謂関数の使い方が載っている公式のAPIリファレンスや、使い方が載っているドキュメンテーションを読めることは大切です。
たまにまともなドキュメントがない場合がありますが、そういう場合はGitHubのREADMEや、examplesがあることが多いので流用したり、最悪ソースコードを読む、といった感じです。間違ってもいきなりソースコードから読んだりしてはいけません。

逆に、自分がプロジェクトを作るときにドキュメントの整備はかなり重要なので意識しましょう。
あと、ドキュメントは`.md`（Markdown）で残すこと。`.txt`などは使いません。大規模なら`.rst`（reStructuredText）でもありっちゃありです。
`.rst`はPythonやLinuxコミュニティでよく使われ、Sphinxというツールを使うと綺麗にまとめることができます。

### サイト内検索や `Ctrl + f` を積極的に使う

サイトの中で特定のキーワードを探すことは割と重要です。一般に `Ctrl+f` を使うことでサイト内検索をすることができます。
GitHubなどはサイトの中で検索が強いのでサイトの機能を積極的に活用していきましょう。

そこまでページ数が多くない場合は `wget` で落としてきて `grep` などで情報を抜いたり、AIに投げてみるのもアリです。

### 英語に怖気づかない

英語の情報の方が圧倒的に多いため、日本語で見つからない情報も積極的に英語で調べる癖をつけましょう。
専門用語は英語でも言えるようにしておきます。そこに英語があるから読むのではなく、自分で英語を使って調べていくスタイルが大事です。
わからないなら翻訳を使えばいいだけです。

### 一次情報を優先に

一次情報をなるべく参照するようにします。一生Qiitaだけ見ていても限界があります。
また、**目的を必ず持って読むこと**。だらだら読んでも意味がありません。

ただし、自身のレベルや時間制約など諸々考えて臨機応変に参照していくことが大切です。
優先順位のイメージは以下の通りです。

1. 公式ドキュメント
2. 仕様書, DataSheet
3. GitHub Issue / PR
4. 技術ブログ
5. そのへんの記事、Reddit

### 検索の精度を意識する

検索ワードの選び方で結果は大きく変わります。

* **Bad:** `ros エラー`
* **Good:** `ROS2 Fast DDS unicast not working domain id same`

## 2. タイピングの大切さ

レポートを書く、チャットする、プログラミング、CLI作業、情報検索……すべてにおいて**キーボードを叩くというアクションが発生します。**
マスターする必要はありませんが、効率が変わってくるのと、タイピングがスムーズにできるといずれにおいても単純にイライラしません。

### 英語タイピングと記号の重要性

とりあえず寿司打をやっておくというのがあるあるですが、**英語タイピングと記号をなぜか大半の人は練習しません。**
プログラミングもコマンドも全部英語ですし、記号も勿論入ってきます。日本人なので日本語は打てるようにするべきですが、同じくらい英語タイピングに時間を割いても良いのではないでしょうか。

### 目標

* **日本語**
  まずタッチタイピング(キーボードを見ずにタイピング)ができるようになること。
  長めの文章を考えながらまったく苦無く打てるようになることが目標です。

* **英語**
  同じくタッチタイピングは基本です。
  簡単なコマンドや英単語なら100wpm(words per minute)は確実に出せるようにしたいところです。
  大文字あり・多少記号アリの長文で80wpm程度出せるようになることが目標です。
  
  正直なところ日本人で100wpm普通に出せる人を自分以外周りでは殆ど見たことがないため、一旦60を目標にして、80 -> 100へステップアップしていくイメージで良いと思います。ただ、それなりに練習しないと到達は不可能です。

* **記号、数字**
  US配列がおすすめですが、JISでも良いです。キーボードをまったく見ること無く記号と数字が打てればとりあえず問題ありません。
  逆に言うと、`@` がどこだとか `|` がどこだとか言っているうちは修行が足りません。
  US配列だと強制的に手元を見ることはなくなりますし、Linuxのデフォルトでもあり、意外と困らないのでずっとこれを使うのも手です。

### どうやるのか

1. 何があってもキーボードを見ない
2. 普段からスマホではなく積極的にPCを使う
3. まずはスピードよりも精度を意識する
4. 毎日少しずつ練習する
5. 終わりはないので定期的に練習する
