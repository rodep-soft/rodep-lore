# 開発者としての基本スキル

ロボット制御やプログラミングを学ぶ前に、まず習得しておくべき重要な基本スキルがある。
ここでは、「情報収集」と「タイピング」についてまとめる。

## 1. 情報収集するということ

素のプログラミング能力や小手先のコマンド芸よりも、**情報収集能力**の方がはるかに大切だ。
有名どころのサイトやリソース元を知っておくことは、開発において非常に役立つ。

### Links (汎用)

1. [StackOverflow](https://stackoverflow.com/questions)
世界中であまりにも有名すぎるエンジニア向け質問サイトだ。

2. [GitHub](https://github.com/)
自分でコードを上げる以外にも、他人のIssueを参考にしたり、リポジトリを覗いたりと付き合いは多い。

3. [Qiita](https://qiita.com/)
日本語圏で一番有名なエンジニアブログサイトだ。みんな使っている。

4. [Zenn](https://zenn.dev/)
こちらも日本語。Qiitaの次に有名なくらいだ。

5. [Reddit](https://www.reddit.com/)
アメリカで有名なSNS。サイト内検索は微妙なので検索エンジンから情報を探すべきだ。
エンジニア特化でもなければ情報の信頼性も微妙だったりするので注意が必要だ。

6. [X/Twitter](https://x.com/home)
情報を探すのにはおすすめしないが、トレンドを掴むにはおすすめだ。

7. [dev.to](https://dev.to/)
英語サイト。微妙な記事も多いが個人的によく見る。Qiitaっぽい雰囲気だ。

### AIを使うことについて

勿論、最近のAIは情報を勝手にSearchしてくれるし、精度も高いため積極的に頼って良いとは思うが、自分で検索して解決しなければならないことも多々あるため、**自分で情報を集めることに慣れる**ことは大切だ。

### 実際のところコード書くときによく見るリソース

有名どころのサイトは挙げたが、実際コーディング中に見るのは、**専らライブラリやフレームワークのドキュメントやセンサーのデータシートなど**だ。

また、Linksに載っているのはあくまで汎用サイトであり、それぞれの言語やフレームワークのフォーラムを見にいくことも多い。
例えばROSだったら ROS Discourse などだ。

所謂関数の使い方が載っている公式のAPIリファレンスや、使い方が載っているドキュメンテーションを読めることは大切だ。
たまにまともなドキュメントがない場合があるが、そういう場合はGitHubのREADMEや、examplesがあることが多いので流用したり、最悪ソースコードを読む、といった感じだ。間違ってもいきなりソースコードから読んだりしてはいけない。

逆に、自分がプロジェクトを作るときにドキュメントの整備はかなり重要なので意識しよう。
あと、ドキュメントは`.md`（Markdown）で残すこと。`.txt`などは使わない。大規模なら`.rst`（reStructuredText）でもありっちゃありだ。
`.rst`はPythonやLinuxコミュニティでよく使われ、Sphinxというツールを使うと綺麗にまとめることができる。

### サイト内検索や `Ctrl + f` を積極的に使う

サイトの中で特定のキーワードを探すことは割と重要だ。一般に `Ctrl+f` を使うことでサイト内検索をすることができる。
GitHubなどはサイトの中で検索が強いのでサイトの機能を積極的に活用していこう。

そこまでページ数が多くない場合は `wget` で落としてきて `grep` などで情報を抜いたり、AIに投げてみるのもアリだ。

### 英語に怖気づかない

英語の情報の方が圧倒的に多いため、日本語で見つからない情報も積極的に英語で調べる癖をつけよう。
専門用語は英語でも言えるようにしておく。そこに英語があるから読むのではなく、自分で英語を使って調べていくスタイルが大事だ。
わからないなら翻訳を使えばいいだけだ。

### 一次情報を優先に

一次情報をなるべく参照するようにする。一生Qiitaだけ見ていても限界がある。
また、**目的を必ず持って読むこと**。だらだら読んでも意味がない。

ただし、自身のレベルや時間制約など諸々考えて臨機応変に参照していくことが大切だ。
優先順位のイメージは以下の通りだ。

1. 公式ドキュメント
2. 仕様書, DataSheet
3. GitHub Issue / PR
4. 技術ブログ
5. そのへんの記事、Reddit

### 検索の精度を意識する

検索ワードの選び方で結果は大きく変わる。

* **Bad:** `ros エラー`
* **Good:** `ROS2 Fast DDS unicast not working domain id same`

## 2. タイピングの大切さ

レポートを書く、チャットする、プログラミング、CLI作業、情報検索……すべてにおいて**キーボードを叩くというアクションが発生する。**
マスターする必要はないが、効率が変わってくるのと、タイピングがスムーズにできるといずれにおいても単純にイライラしない。

### 英語タイピングと記号の重要性

とりあえず寿司打をやっておくというのがあるあるだが、**英語タイピングと記号をなぜか大半の人は練習しない。**
プログラミングもコマンドも全部英語だし、記号も勿論入ってくる。日本人なので日本語は打てるようにするべきだが、同じくらい英語タイピングに時間を割いても良いのではないか。

### 目標

* **日本語**
  まずタッチタイピング(キーボードを見ずにタイピング)ができるようになること。
  長めの文章を考えながらまったく苦無く打てるようになることが目標だ。

* **英語**
  同じくタッチタイピングは基本だ。
  簡単なコマンドや英単語なら100wpm(words per minute)は確実に出せるようにしたい。
  大文字あり・多少記号アリの長文で80wpm程度出せるようになることが目標だ。
  
  正直なところ日本人で100wpm普通に出せる人を自分以外周りでは殆ど見たことがないため、一旦60を目標にして、80 -> 100へステップアップしていくイメージで良い。ただ、それなりに練習しないと到達は不可能だ。

* **記号、数字**
  US配列がおすすめだが、JISでも良い。キーボードをまったく見ること無く記号と数字が打てればとりあえず問題ない。
  逆に言うと、`@` がどこだとか `|` がどこだとか言っているうちは修行が足りない。
  US配列だと強制的に手元を見ることはなくなるし、Linuxのデフォルトでもあり、意外と困らないのでずっとこれを使うのも手だ。

### どうやるのか

1. 何があってもキーボードを見ない
2. 普段からスマホではなく積極的にPCを使う
3. まずはスピードよりも精度を意識する
4. 毎日少しずつ練習する
5. 終わりはないので定期的に練習する
