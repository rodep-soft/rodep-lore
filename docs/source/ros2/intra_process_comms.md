# プロセス内通信（IPC）とComponent設計

大容量のセンサデータ（高解像度カメラ画像や3D LiDARの点群データなど）をノード間で頻繁に受け渡す場合、DDSを介したシリアライズとデシリアライズの処理がCPUリソースを著しく消費し、通信レイテンシを悪化させます。この課題を解決する鍵が、プロセス内通信（Intra-process Communication）とComponentアーキテクチャです。

## ゼロコピー通信の実現

ROS 2では、ノード初期化時に `rclcpp::NodeOptions().use_intra_process_comms(true)` を指定することで、同一プロセス内で稼働するノード間の通信において、DDSスタックをバイパスさせることが可能です。
さらに、メッセージデータを `std::unique_ptr` を用いてパブリッシュし、サブスクライブ側でも `std::unique_ptr` で受け取るように実装することで、メモリ空間上でのデータポインタの移動のみで通信が完了します。この「ゼロコピー通信」により、データサイズに依存しない極めて高速な伝送が実現し、メモリ帯域の消費を劇的に削減できます。

## Componentアーキテクチャの実践

プロセス内通信の恩恵を受けるためには、複数のノードを単一のOSプロセス上で稼働させる必要があります。ROS 2では、ノードを共有ライブラリ（Component）としてビルドし、実行時にコンテナプロセス（Component Container）へ動的にロードする仕組みが提供されています（`rclcpp_components`）。

この設計手法を採用することで、開発時は各機能を独立したモジュールとして扱い、デプロイメント時にLaunchファイルを通じて同一プロセスへの統合（Composition）を行うことが可能となります。システムの構成を柔軟に変更でき、本番環境でのパフォーマンス要求と開発時のテスト容易性を両立させる強力なアプローチです。
