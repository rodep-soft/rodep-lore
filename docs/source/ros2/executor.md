# ExecutorとCallback Groupの高度なスレッド管理

ROS 2におけるメッセージの受信やタイマー処理の実行は、Executorと呼ばれるコンポーネントによって管理されます。ロボットの応答性を高め、リアルタイム性を担保するためには、この実行制御モデルを深く理解する必要があります。

## SingleThreadedExecutor の限界

デフォルトで採用されている `SingleThreadedExecutor` は、単一のスレッドで全てのコールバックを順番に処理します。設計がシンプルである反面、画像処理などの計算負荷が高いコールバックや、ファイルI/Oでブロックされる処理が含まれていると、スレッド全体が停止し、他の重要な制御ループやメッセージ受信が遅延するという深刻なボトルネックを引き起こします。

## MultiThreadedExecutor と Callback Group

複雑なシステムにおいては、`MultiThreadedExecutor` の導入が必須となります。これを利用することで、複数のコールバックを異なるスレッドで並行して実行できます。
並行実行の制御は、ノード内で定義する `Callback Group` によって細やかに設定します。Callback Groupには以下の2種類が存在します。

* **MutuallyExclusive（排他実行）**
  同一グループ内のコールバックは、同時に実行されないことが保証されます。スレッドセーフでない状態変数を操作する場合や、リソースの競合を防ぐ場合に利用します。
* **Reentrant（並行実行可能）**
  同一グループ内のコールバックであっても、利用可能なスレッドがあれば同時に実行されます。独立した処理を効率的に分散させる場合に適しています。

## スレッド割り当てのベストプラクティス

高頻度かつ低遅延が要求される制御ループ（タイマーコールバック）と、低頻度なパラメータ更新やログ出力のコールバックは、異なる `MutuallyExclusive` グループに分離することが推奨されます。これにより、重い処理が制御ループの実行周期を阻害するリスクを劇的に低減できます。

## 今後の展望：Events Executor

rclcppの実験的な機能として、よりオーバーヘッドの少ない `Events Executor` などの新しい仕組みが開発されています。従来のポーリングベースの実行待ちから、DDSレベルのイベント通知を直接トリガーとするアーキテクチャへと進化しており、将来的にはさらに細かなリアルタイム性の制御が可能になると期待されています。
