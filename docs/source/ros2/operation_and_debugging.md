# ロボットシステム運用とデバッグの実践的作法

ROS 2を用いたロボットソフトウェア開発において、システムが複雑化するほど、標準ツールと定石（ベストプラクティス）の活用がプロジェクトの成否を分けます。

## `twist_mux` による安全な指令統合

手動操作用のジョイスティック、ナビゲーションスタック（Nav2）、安全用の障害物検知ノードなど、複数のソースからロボットの速度指令（`cmd_vel`）が非同期に発行される状況は極めて一般的です。
アプリケーションコード内で独自に条件分岐を記述してこれらを調停するのはアンチパターンです。ROSの標準機能である `twist_mux` を導入し、各指令ソースに対する優先度とタイムアウトをYAMLファイルで宣言的に定義することが定石です。これにより、通信断絶時や緊急停止フラグが立った際に、低優先度の安全な指令へと自動的にフォールバックする堅牢な機構を容易に構築できます。

## `use_sim_time` の確実な管理

Gazeboなどのシミュレータ環境や、`ros2 bag` による収録データの再生時において、システム時刻ではなくシミュレーション上の論理時刻を使用することは極めて重要です。
ノードのパラメータとして `use_sim_time:=true` を付与し忘れると、受信したデータのタイムスタンプと現在のシステム時刻に致命的なズレが生じます。その結果、TFツリーのルックアップが過去または未来のデータとして棄却され、ナビゲーションやマニピュレーションが完全に機能不全に陥ります。Launchファイル内でこのパラメータを一元的に管理し、全ノードへ確実に伝搬させる設計を取り入れることが望ましいです。

## センサフュージョンと Dual EKF

IMU、車輪のエンコーダ、GPSなど特性の異なるセンサ情報を統合し、高精度な自己位置推定を行うためには、`robot_localization` パッケージの利用がデファクトスタンダードです。
屋外の自律移動ロボットにおいては、短期間で高精度な相対移動量を推定するローカルEKF（`odom` から `base_link` のTFを発行）と、GPSなどの絶対座標を組み合わせて長期間のドリフトを補正するグローバルEKF（`map` から `odom` のTFを発行）を併用する「Dual EKF」構成を採用することで、連続的かつ滑らかな制御と、大局的な位置精度の両立が可能となります。

## 標準メッセージ規格の遵守

トピックやサービスのインターフェースを設計する際、独自のメッセージ型（カスタムインタフェース）を安易に定義することは避けるべきです。
原則として `std_msgs`、`sensor_msgs`、`geometry_msgs` などの標準化された型を最大限に活用します。標準型を使用することで、`ros2 bag` によるデータの記録・再生、`rqt` や `Foxglove Studio` といった強力な可視化ツール群との完全な互換性が担保され、チーム内外でのソフトウェアの相互運用性が飛躍的に向上します。
