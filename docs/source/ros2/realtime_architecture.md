# リアルタイム制御とシステムアーキテクチャ設計

ロボットの多関節制御や高速な自律走行など、厳密な時間制約とマイクロ秒単位のジッタ低減が求められるシステムにおいて、ROS 2をリアルタイムOS（RTOS）や PREEMPT_RT パッチを適用した Linux カーネルと組み合わせるアーキテクチャが採用されます。

## メモリ管理とページフォールトの回避

リアルタイム性を損なう最大の要因の一つは、OSによる予期せぬ割り込みとメモリ管理の遅延です。
これを防ぐため、プロセス起動時に `mlockall` を呼び出し、仮想メモリがスワップ領域に退避されること（ページフォールト）を物理メモリ上にロックして完全に阻止します。
また、リアルタイム処理を担うコールバックやスレッド内では、動的なメモリ確保（`new` や `malloc`）を厳禁とします。STLコンテナのサイズは初期化時に事前に確保（`reserve`）するか、カスタムアロケータ（TLSFなど）を活用して決定論的なメモリ操作を徹底することが求められます。

## スケジューリングと優先度の最適化

リアルタイムスレッドに対しては、カーネルのスケジューリングポリシーを `SCHED_FIFO` や `SCHED_RR` に設定し、適切な優先度を付与します。
ROS 2では、DDSの中核的なスレッドや、Executorの実行スレッドに対して個別に優先度を割り当てることが可能です。ただし、優先度を不適切に高く設定すると、OSのネットワークドライバやシステムプロセスの実行を阻害し、かえって全体のパフォーマンスを低下させるリスクがあるため、システム全体のプロファイリングに基づいた慎重な設計が必要です。

## ノード分割粒度のトレードオフ

システムを機能ごとに細かくノード（マイクロサービス）に分割することは、保守性や単体テストの容易さを向上させます。しかし、過度な細分化はDDS上のトピック数を不必要に増大させ、ディスカバリの負荷やシリアライズのオーバーヘッドを引き起こします。
リアルタイム制約の厳しい制御ループや、密結合なセンサ処理パイプラインは一つのComponent内に統合してプロセス内通信を活用し、システム全体の状態管理や外界とのインターフェース境界ではDDS通信を介するといった、バランスの取れたハイブリッドな設計アプローチが推奨されます。
