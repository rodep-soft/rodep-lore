# ROS2 のデバッグ・実装手法・システムアーキテクチャ

お疲れ様！今日はROS2のデバッグや実装手法、システムアーキテクチャ周りの大事な知見を共有していくね。これを知ってるかどうかで開発のスピードが全然変わってくるから、しっかり覚えていってほしいなと思っています！

## (1) ノード設計・プロセス内通信・コンポーネント化

### ノード分割のトレードオフ
まずノード設計なんだけど、機能ごとに細かく分けると耐障害性は上がるよね。でも、細かくしすぎると今度はDDS通信のオーバーヘッドが重くなってくるというわけです。このバランス感覚が大事！

### プロセス内通信（Intra-process Communication / Zero-Copy）と Component
大容量の画像データとか、めっちゃ高頻度な制御でゼロコピー転送をやりたい時ってあるよね。そういう時は、`rclcpp::NodeOptions().use_intra_process_comms(true)` を有効にして、メッセージを `std::unique_ptr` で publish/subscribe する必要があります！
これを実現するためには、ノードを共有ライブラリ（Component）としてビルドして、単一のプロセスに動的ロードするっていう構成を取るんだよね。ちょっと難しそうに見えるけど、慣れればなんてことないよ笑

### `twist_mux` による速度指令の安全統合
手動操作（Joystick）と自動航行（Nav2）みたいに、複数の速度指令がぶつかることってよくあるよね。こういう時、自前で `switch` 文とか書いて制御したくなる気持ちはわかるんだけど、それはアンチパターン！標準の **`twist_mux`** を導入して、優先度とタイムアウトを使って安全に統合するのが正解というわけです。

## (2) デバッグ・シミュレーション・トピックの作法

### `use_sim_time:=true` の罠
これ、マジでみんな一度はハマる罠なんだけど（笑）、Gazeboとかのシミュレーション環境やROS Bag再生時に `use_sim_time:=true` をノードに渡し忘れると、TF（座標変換）とかMoveIt2、Nav2がピタッと動かなくなっちゃうんだよね。実機で動かす時は `false` でいいんだけど、シミュレーション時は絶対に忘れないようにね！

### シミュレーションと実機の透過的切替
トピックの仕様を共通化した仮想コントロールパネルみたいなのを作っておくと、コードを一切いじらずにシミュレーションと実機をサクッと切り替えてテストできるようになるよ。これ、めちゃくちゃ便利だから絶対やってみてほしいなと思っています。

### `robot_localization` (EKF / Dual EKF)
IMUとか車輪エンコーダのセンサ統合には、おとなしく `robot_localization` を使いましょう。自己位置推定の時は、ローカル用EKF（`odom` -> `base_link`）とグローバル用EKF（`map` -> `odom`）を組み合わせる **Dual EKF** 構成がデファクトスタンダードですよね。

### 標準メッセージ規格の尊重
最後にトピックの作法なんだけど、独自のトピック構造体をむやみに作るのはやめようね！基本的には `std_msgs`, `sensor_msgs`, `geometry_msgs` みたいな標準を優先して使うこと。
CAN通信でも、各ドライバで独自のものを定義するんじゃなくて、ROS2標準規格の **`can_msgs/msg/Frame`** に依存してノードを作るのが、今後の相互運用性を考えると極めて重要になってくるというわけです！
