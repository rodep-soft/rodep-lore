# cgroupsによるリソース分離とリアルタイム性確保

ロボットシステム上では、画像処理、経路計画、センサー制御など、計算負荷や要求されるリアルタイム性が異なる多数のプロセスが同時に稼働します。これらが限られたCPUやメモリリソースを奪い合い、ミッションクリティカルな処理が遅延する事態は避ける必要があります。このような場面で不可欠となるのが、`cgroups`（Control Groups）による厳格なリソース分離です。

現代のLinuxでは、階層構造が統合された `cgroups v2` が主流となっています。これにより、システム内の特定のサービスやプロセスグループに対して、CPU使用時間（`cpu.max`）やメモリ使用量の上限を設けることが容易になりました。特にメモリ管理においては、ハードリミットである `memory.max` だけでなく、スワップやページキャッシュの回収を促すソフトリミットの `memory.high` を適切に設定することで、システム全体のOOM（Out Of Memory）によるパニックを未然に防ぐことが可能です。

メモリ枯渇時にシステムを守るOOM Killerの挙動制御も重要です。例えば、モータ制御ノードなど絶対に停止してはならないプロセスに対しては、`/proc/<pid>/oom_score_adj` に負の値を設定し、キル対象から除外する措置が求められます。
さらに、厳密なタイミングが要求される処理には、カーネルの `PREEMPT_RT` パッチの導入を検討するとともに、`chrt` コマンドを使用してスケジューリングポリシーを `SCHED_FIFO` や `SCHED_RR` へ変更し、CPUコアを占有させる `isolcpus` や `taskset` と組み合わせることで、確実な実行レイテンシを担保するチューニングが実践されます。
