# Dockerの内部構造とLinuxカーネルの機能

コンテナ技術を支える基盤技術であるNamespaceとCgroup、そしてDocker Engineの変遷について解説します。

## NamespaceとCgroup

コンテナは仮想マシンとは異なり、ホストOSのカーネルを共有します。Dockerデーモン（`dockerd`）は、Linuxカーネルの機能である「Namespace」を利用してプロセス、ネットワーク、マウントポイントなどを隔離し、「Cgroup」を利用してCPUやメモリのリソース制限を適用します。これにより、コンテナ内のプロセスからは独立したOSのように見えます。

## Dockerアーキテクチャの変遷

初期のDockerは巨大な単一のデーモンがすべてを管理していましたが、現在ではモジュール化が進行しています。具体的には、`dockerd`がリクエストを受け取り、`containerd`（コンテナのライフサイクル管理）に処理を委譲し、最終的に`runc`という低レベルランタイムがNamespaceやCgroupの設定を行ってプロセスを起動します。この仕組みにより、KubernetesなどもDockerに依存せず、直接`containerd`を利用する構成が標準化されました。

## ネットワークとセキュリティ

コンテナのネットワーク設定において、`network_mode: host`や`privileged: true`を安易に指定することは、ホストのネットワーク名前空間やリソースへの無制限なアクセスを許可することと同義であり、セキュリティ上の大きなリスクを伴います。例えば、コンテナ内に不正侵入された場合、ホストネットワーク上の他のデバイスに対してARPスプーフィングなどの中間者攻撃が容易に行われる危険性があります。Linuxにおいてネットワークインターフェースの設定を変更するには`CAP_NET_ADMIN`権限が必要であるという基本原則を理解しておくことが重要です。
