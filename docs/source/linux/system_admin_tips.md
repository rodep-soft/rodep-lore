# Linuxのコマンド・システム運用・シェルスクリプトの知見

Linuxのコマンド、システム運用、およびシェルスクリプトに関して、実践を通して得られた知見を共有します。
単なるコマンドリファレンスではなく、実際の現場での利用方法や陥りやすい落とし穴といった実用的な情報をまとめています。システム運用の要点を把握する一助となれば幸いです。

## 1. ファイルシステムとLinuxの本質
まず理解しておきたいのは、Inodeの役割です。
Inodeはデータそのものではなく、ディスク上のブロックを指し示す「ポインタ構造体」として機能します。したがって、ファイルの本質は「名前や拡張子」には存在しません。Windows環境などでは拡張子でファイルの種類を判断しがちですが、Linuxにおいて拡張子は単なる文字列に過ぎません。ファイルが実行可能かどうかは、パーミッションやマジックバイトによって決定されます。この感覚を持っておくことは非常に重要でしょう。なお、空のディレクトリをまとめて削除する際には `rmdir -p` を用いると便利です。

また、Arch LinuxやUbuntuなどを運用する上では、定期的なメンテナンスも欠かせません。
`yay`、`docker`、`pacman` などを頻繁に利用していると、ビルドキャッシュなどが蓄積し、ストレージ容量を容易に圧迫します。定期的に `docker system df` や `pacman -Scc` などを実行し、不要なデータを整理してシステムを清潔に保つことが運用における基本となります。

## 2. ログ調査とプロセスデバッグ
トラブルシューティングにおけるログの確認方法について触れておきます。
大量のログを調査する際の基本は、`less` と `journalctl` の活用です。UbuntuやArch Linuxではシステムサービスのログが `journalctl` に集約されているため、問題発生時にはまず `journalctl -u gdm.service` のようにサービスを指定してログを確認することが解決への第一歩となります。

さらに、カーネルやプロセスの状態を詳細に把握するためには、`/proc` や `/sys` の構造を理解しておくことが重要です。例えば `/proc/<pid>/stack` を確認すれば、プロセスが `futex_wait` で停止しているかどうかが容易に判別できます。システムコールの解析には `strace` を併用する手法が効果的でしょう。

プロセスをバックグラウンドで実行する際は `nohup command &` が手軽ですが、実際の運用環境では要件に応じて `tmux` や `systemd` によるサービス化を使い分けることが求められます。
ROSノードが暴走して停止できなくなった場合の対処法として、以下のコマンドが有用です。

```bash
pkill -9 -f ros && ros2 daemon stop
```

これにより、バックグラウンドのデーモンおよびノードを確実に停止させることができます。

## 3. ネットワーク運用とDNSの注意点
ネットワーク関連のトラブルは解決に時間を要することが少なくありません。
よくある事例として、`nslookup` と `systemd-resolved` の挙動の違いが挙げられます。`systemd-resolved` 環境下では、`nslookup` や `/etc/resolv.conf` の参照先がローカルループバック（127.0.0.53など）になっている場合があります。そのため、実際に行われている名前解決の参照先を確認したい場合は、`resolvctl status` を実行するのが適切なアプローチとなります。

また、ファイアウォールやNATの設定で `iptables` や `nftables` を操作することがありますが、これらは設定のためのインターフェース（フロントエンド）に過ぎず、実体はカーネルモジュールの `netfilter` です。こうした本質的な構造を理解しておくことで、デバッグの精度が向上します。ネットワークのデバッグにおいて `traceroute` でICMPやTCPパケットを送信したい場合、`sudo traceroute -T <target>` のように特権が必要となる点にも留意が必要です。

TailscaleなどのメッシュVPNを利用している環境では、ローカルの `/etc/hosts` に古い情報が残存していると、MagicDNSよりも優先されてしまい通信に失敗するケースがあります。鍵の有効期限（expire）も含め、定期的に設定を見直す習慣をつけることが望ましいでしょう。

## 4. シェルスクリプトの留意点とPythonの活用
最後に、シェルスクリプトに関する留意点です。Fishシェルは便利ですが、Fishでスクリプトを記述するとBashやZsh環境との互換性が損なわれ、自動化の際に問題を引き起こす原因となります。
数行を超えるような複雑な自動化処理については、シェルスクリプトに固執せず、Pythonの `subprocess` や `os` モジュールを利用して記述することをお勧めします。これにより、保守性と移植性を大幅に向上させることが可能です。

また、プログラミング経験者が陥りやすい点として、終了ステータス（Exit Code）の解釈の違いがあります。
Unix/Linux環境のコマンドにおいては、終了コード `0` が「成功」を表します。これは一般的なプログラミング言語における真偽値（`True=1`, `False=0`）の概念とは逆であるため、シェルスクリプトと連携させて条件分岐を行う際には十分に注意する必要があります。
