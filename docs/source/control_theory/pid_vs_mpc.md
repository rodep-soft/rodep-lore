# Pid Vs Mpc

## ロボット制御理論：PID制御からモデル予測制御(MPC)まで

ロボットの挙動を意図した通りに操作するためには、物理現象のモデル化と適切な制御アルゴリズムの選定が不可欠です。本稿では、モータレベルの低位制御から、システム全体の経路追従を行う上位制御までの階層的アプローチについて、古典的なPID制御と先進的なモデル予測制御（MPC）の比較を交えて解説します。

### 1. 制御の階層構造と閉ループ系の必要性

ロボットの制御アーキテクチャは、一般にカスケード（階層型）制御として設計されます。
例えば、自律移動ロボットの場合、以下のようなレイヤー構造をとります。

1. **上位レイヤー（経路追従・速度生成）**:
   目標軌道と現在位置（自己位置推定結果）の偏差に基づき、機体全体の目標並進速度および目標旋回角速度（Yaw rate）を算出します。
2. **下位レイヤー（モータ駆動）**:
   上位から渡された目標速度を各車輪の回転速度に変換（逆運動学）し、各モータに対して電流やPWM指令値を決定します。

「一定の出力を与えれば、理論上の速度で移動するだろう」というオープンループ（開ループ）な発想は、慣性、摩擦、外乱が存在する実世界では通用しません。エンコーダやIMUから「実際にどれだけ動いたか」を取得し、そのフィードバックを元に制御入力を補正する閉ループ（Closed Loop）系が必須となります。

### 2. PID制御の再評価と限界

古典制御理論の代表であるPID（比例・積分・微分）制御は、実装の容易さと多くのシステムでの有効性から、下位モータ制御などで現在でも広く用いられています。

$$ u(t) = K_p e(t) + K_i \int_{0}^{t} e(\tau) d\tau + K_d \frac{de(t)}{dt} $$

- **P（比例）**: 偏差に比例した出力を生成。
- **I（積分）**: 定常偏差を解消。
- **D（微分）**: 偏差の変化率に基づき、オーバーシュートやふらつきを抑制。

ロボットは質量や慣性モーメントを持つ高次系（2次遅れ系など）として振る舞うため、Dゲインによるダンピング効果がふらつきの抑制に極めて重要です。
一方で、PID制御には以下の限界があります。
- システムの非線形性に対する適応力が低い。
- アクチュエータの飽和（出力の限界）などの制約条件を明示的に扱えない。
- 複数入力・複数出力（MIMO）系の干渉を考慮しにくい。

### 3. モデル予測制御（MPC）の導入

高度な制御要件を満たすため、近年ではモデル予測制御（MPC: Model Predictive Control）や、非線形モデル予測制御（NMPC）への注目が高まっています。

MPCの基本思想は、「現在の状態から未来の一定区間（ホライズン）におけるシステムの挙動を内部モデルを用いて予測し、評価関数を最小化するような最適入力系列を計算する。そして、その入力系列の最初のステップのみを実際のシステムに適用する（Receding Horizon制御）」というものです。

#### 評価関数と制約条件

離散時間モデル $x_{k+1} = f(x_k, u_k)$ において、評価関数 $J$ は以下のように設計されます。

$$ J = \sum_{i=0}^{N-1} \left( \| x_{k+i} - x_{ref, k+i} \|_{Q}^2 + \| u_{k+i} \|_{R}^2 \right) + \| x_{k+N} - x_{ref, k+N} \|_{P}^2 $$

ここで、$N$ は予測ホライズン、$Q, R, P$ は重み行列です。
同時に、以下の制約条件を満たす必要があります。
- 状態制約: $x_{min} \leq x_{k+i} \leq x_{max}$ （障害物回避など）
- 入力制約: $u_{min} \leq u_{k+i} \leq u_{max}$ （モータの最大出力など）

#### 実装の課題とROS2環境での可能性

MPC、特に非線形方程式をそのまま解くNMPCは、計算量が「馬鹿重い」という致命的な欠点があります。実時間（数ミリ〜数十ミリ秒周期）で最適化問題を解き続ける必要があるため、計算資源の限られた組み込みマイコンでは実行が困難です。

しかし、近年のROS2（Robot Operating System 2）ベースのシステムでは、演算を高性能なSBC（シングルボードコンピュータ）やPC側にオフロードすることが可能です。`nav2_mppi_controller`などのソルバを利用することで、高度な非線形制御も現実的な計算時間で動作させることが可能になりつつあります。

### 4. トレードオフの判断

システム要件に対して、必ずしもMPCのような高級な制御理論が必要とは限りません。「小難しい制御を取り入れたい」という目的化は避けるべきです。
- 各モータの回転数制御など、線形近似が有効で独立性の高いループにはPID制御。
- 車両全体の軌道追従など、制約条件の考慮や非線形性が強いタスクにはMPC。
適材適所で制御手法を使い分けるカスケード設計こそが、実践的なロボティクスエンジニアリングの最適解と言えます。

## PID制御とモデル予測制御（MPC）のリアルタイム処理の比較

ロボットの運動制御において、PID（比例・積分・微分）制御は、その実装の容易さと多くの非線形システムに対しても実用的な安定性を提供できる点から、依然として主流の制御手法です。

一方で、より高度な制御手法としてモデル予測制御（MPC: Model Predictive Control）が注目されています。MPCは、対象システムの数理モデルを用いて未来の挙動を予測し、制約条件を満たしつつ最適な制御入力を算出します。しかし、MPCは各サンプリング周期ごとに複雑な最適化問題を解く必要があるため、計算負荷が極めて高く、リアルタイム性の確保が技術的な障壁となります。

ROS 2環境では、高性能なソルバーを用いることでMPCの実時間動作も視野に入ってきますが、対象の厳密なモデル化が前提となるため、導入コストが高いのが実情です。そのため、用途やハードウェアの計算リソース（組み込みマイコンか高スペックなシングルボードコンピュータか）に応じて、シンプルなPID制御と高度なMPCを適切に使い分ける設計判断が求められます。
